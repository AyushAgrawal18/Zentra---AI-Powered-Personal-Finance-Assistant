# 1. Purpose

This document defines how development work is planned and tracked on a weekly basis.

The objective is to maintain consistent progress while ensuring that every feature is completed with proper documentation, testing, and review.

Weekly goals should always align with the project roadmap.

---

# 2. Objectives

Every week should aim to:

- Complete planned features.
- Avoid unfinished work.
- Maintain documentation.
- Improve project quality.
- Reduce technical debt.
- Prepare the next week's work.

# 4. Weekly Planning

At the beginning of every week:

- Review completed work.
- Review pending tasks.
- Select achievable goals.
- Estimate development effort.
- Identify dependencies.
- Record risks or blockers.

Avoid planning more work than can reasonably be completed.

---

# 5. Weekly Review

At the end of every week, review:

## Development

- Features completed
- Features in progress
- Features postponed

---

## Documentation

- Documentation updated
- Missing documents
- Architecture changes

---

## Code Quality

- Refactoring completed
- Bugs fixed
- Technical debt reduced

---

## Testing

- Unit tests added
- Integration tests completed
- Regression issues resolved

# 8. Rules

Always:

- Finish current tasks before starting new ones.
- Keep documentation synchronized with development.
- Resolve critical bugs before adding features.
- Review progress every week.
- Update the roadmap when priorities change.

Never:

- Leave completed work undocumented.
- Carry unnecessary unfinished tasks into the next week.
- Skip testing to meet deadlines.
- Change architecture without documenting the decision.

---

# 9. Success Criteria

A successful week is one in which:

- Planned objectives are completed.
- Documentation remains up to date.
- Code quality is maintained.
- No critical bugs remain unresolved.
- The project moves measurably closer to the next milestone.
